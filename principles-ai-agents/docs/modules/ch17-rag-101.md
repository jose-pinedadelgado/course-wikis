# Chapter 17 — RAG 101

## What Is RAG?

**Retrieval-Augmented Generation** — instead of relying solely on the model's training data, you **retrieve relevant documents** and include them in the prompt.

!!! quote "The Simple Idea"
    Search a knowledge base → grab the most relevant chunks → stuff them into the prompt → let the model generate an answer using that context.

## The Pipeline

```
User Query → Embed → Search Vector DB → Retrieve Top-K → Augment Prompt → Generate
```

### Key Steps

1. **Chunking** — Split documents into manageable pieces
2. **Embedding** — Convert chunks to vector representations
3. **Indexing** — Store vectors in a vector database
4. **Retrieval** — Find the most similar vectors to the user's query
5. **Augmentation** — Add retrieved chunks to the prompt
6. **Generation** — LLM produces the answer

## Chunking Strategies

| Strategy | Pros | Cons |
|----------|------|------|
| **Fixed-size** (e.g., 500 tokens) | Simple, predictable | May split mid-sentence |
| **Semantic** (by paragraph/section) | Preserves meaning | Variable sizes |
| **Recursive** | Balanced | More complex |

!!! warning "Don't Over-Engineer RAG"
    Before building a RAG pipeline, ask: **does the entire document fit in the context window?** If so, just load it all. RAG adds complexity that may not be needed.
